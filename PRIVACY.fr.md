## 6. RUSE Guard : notre anti-triche (obligatoire)

Pourquoi : pour empêcher la triche dans les parties multijoueur et coopératives de R.U.S.E. jouées avec des copies que nos applications construisent. Les mods peuvent changer la façon dont le jeu se joue. Chaque copie dont les mods changent le jeu reçoit donc un code de partie que vous comparez avec les personnes avec qui vous jouez. Une copie construite avec une triche ou un outil de test vérifie que chaque joueur de la partie a la même version de build, et abandonne la partie sinon. Dans les parties multijoueur et coopératives, RUSE Guard cherche aussi des outils de triche connus qui tournent sur votre PC. Et le surveillant de chaque copie affiche à l'écran quand une partie voit un ordre d'apparition ou un bond soudain de l'argent d'un camp.

Pourquoi c'est obligatoire : RUSE Guard est obligatoire pour utiliser nos applications. R.U.S.E. n'a pas d'anti-triche efficace, et c'est pourquoi RUSE Guard est nécessaire : il aide à tenir les tricheurs hors du multijoueur, et les parties équitables comptent pour nous et pour chaque joueur que vous rencontrez. Nous nous appuyons sur ce que le droit de la protection des données appelle un « intérêt légitime » : des parties équitables pour tous les joueurs, ce qui n'exige pas votre autorisation tant que votre vie privée ne l'emporte pas sur cet intérêt (section 11). C'est pourquoi ce n'est pas une case à cocher comme Bug Watch : le Studio et le Launcher tels que nous les publions l'incluent toujours. Vous pouvez quand même vous y opposer à tout moment (section 11).

- Où il agit : RUSE Guard est dans chaque copie moddée que les applications construisent, et le Jeu d'origine du Launcher construit lui aussi une telle copie, sans mods (section 10). Son verrou et sa vérification des programmes n'agissent que dans les parties multijoueur et coopératives, et il en irait de même pour ses enregistrements de partie, une fois qu'ils commenceront (ci-dessous). Son surveillant, présent lui aussi dans chaque copie moddée, observe les parties multijoueur, coopératives et les escarmouches contre l'ordinateur : il peut afficher un message sur votre propre écran quand l'argent d'un camp fait un bond de 400 ou plus d'un coup, ou quand une unité est créée par un ordre d'apparition. Dans une partie multijoueur, l'écran de chaque joueur peut l'afficher. Le surveillant ne change rien dans la partie et n'envoie rien. Seul le Launcher envoie quelque chose pour RUSE Guard ; le Studio n'en envoie jamais, et son Tester en jeu ne lance aucune vérification des programmes.
- La liste : la liste d'outils de triche connus de RUSE Guard est fournie dans l'application, sous forme de simple fichier que vous pouvez lire, et ne change qu'avec une mise à jour de l'application. Rien n'est téléchargé pour elle.
- La vérification des programmes : dans une partie multijoueur ou coopérative lancée depuis le Launcher, RUSE Guard regarde toutes les 30 secondes les noms des programmes qui tournent sur votre PC, et ne garde que les noms qui figurent sur sa liste. Pour savoir quand une telle partie est en cours, le Launcher lit la sortie d'erreurs du jeu pendant qu'il tourne : il ne garde que les courtes lignes de RUSE Guard qui disent qu'une partie est en cours ou terminée, et jette toutes les autres lignes dès qu'il les lit, sans jamais les garder ni les envoyer (cette sortie peut aussi contenir des lignes de Steam, dont l'une avec le numéro de votre compte Steam). Si le jeu ne dit pas qu'une partie est terminée, la vérification s'arrête deux minutes après la dernière fois où le jeu a dit qu'elle était en cours. Si un programme listé tournait pendant une partie, le Launcher envoie à notre serveur, après la partie, un court enregistrement : votre nom d'utilisateur et votre clé RUSE Guard, le début et la fin de la partie, s'il s'agissait de multijoueur ou de coopératif, et les noms des programmes listés trouvés. Rien d'autre n'y figure : ni replay, ni fichiers, ni rien de plus sur la partie. Si aucun programme listé ne tournait, rien n'est envoyé.
- Le code de partie : pour une copie moddée dont les mods changent la façon dont le jeu se joue, le Launcher affiche un code de partie. Il représente la version du jeu de la copie, ses mods avec leurs versions, et ce qu'ils changent dans la façon dont le jeu se joue. Vous comparez les codes de partie avec les personnes avec qui vous jouez. Nous ne les recevons pas aujourd'hui ; un enregistrement de partie (ci-dessous) les porterait.
- Les copies construites avec un outil de triche ou de test : une telle copie ne joue en multijoueur et en coopératif qu'avec des joueurs dont le build est le même (même version du jeu et mêmes mods, dans les mêmes versions). Environ une seconde après le début de chacune de ces parties, elle indique au jeu de chaque joueur un court code de son build (son code de build), calculé à partir de la version du jeu, des mods avec leurs versions dans leur ordre, et de ce qu'ils changent dans la façon dont le jeu se joue. Il ne contient ni nom ni compte. Si tous les joueurs ont le même build, la partie est conçue pour continuer ; personne n'a encore joué une telle partie à deux. Sinon, elle abandonne la partie quelques secondes après le début.

  Dans une partie multijoueur non classée, elle arrête ensuite le jeu exprès à l'écran de fin de cette partie : le jeu plante et revient au bureau. Le rapporteur de plantage du jeu lui-même peut alors envoyer son rapport au créateur du jeu, et ce rapport contient la ligne de RUSE Guard disant qu'une copie de triche a été arrêtée. Dans les parties coopératives et classées, elle se contente d'abandonner la partie. Quand le Launcher a lancé le jeu et est encore ouvert au moment où le jeu s'arrête, il ne prend que la ligne de RUSE Guard dans le rapport de plantage du jeu sur votre PC et envoie à notre serveur une courte note disant qu'une copie de triche a été arrêtée, sous votre nom d'utilisateur et votre clé RUSE Guard, avec le moment où le rapport de plantage a été écrit et celui où la note a été faite. La ligne ne dit que le type de partie et le numéro de votre camp dans celle-ci ; tout identifiant Steam, long nombre ou chemin en est retiré. Nos applications n'envoient jamais le rapport de plantage lui-même. La note n'ouvre aucune revue et ne décide rien ; elle est listée pour que sneadtristen6 la voie. Aucune note n'est envoyée si le Launcher a été fermé avant que le jeu ne s'arrête, ou si le jeu a été lancé depuis le Studio ou à la main. Sous Linux et sur le Steam Deck, on ne sait pas encore si la note est envoyée.

  Les copies honnêtes ne sont jamais arrêtées.

- Votre clé RUSE Guard : la première fois que le Launcher fait un enregistrement RUSE Guard sur votre PC, il y crée une clé aléatoire. Un code calculé à partir de cette clé (sa moitié publique) accompagne chaque enregistrement, pour que nous puissions distinguer vos enregistrements de ceux de quelqu'un qui a le même nom d'utilisateur, et vérifier qu'ils n'ont pas été modifiés. Il ne dit rien d'autre sur vous. Les Réglages affichent un court code calculé à partir d'elle, « Votre code RUSE Guard » : envoyez-le avec une demande relative à la vie privée, et nous pourrons retrouver vos propres enregistrements RUSE Guard. Rien de plus n'est envoyé pour cela.
- Pas encore actif : les enregistrements de partie. Ils ont besoin d'un enregistrement de la partie que le jeu ne sait pas écrire aujourd'hui. Avant qu'ils commencent, nous mettrons ce texte à jour, et les applications vous le montreront de nouveau. Quand ils commenceront, un enregistrement de partie portera : votre nom d'utilisateur et votre clé RUSE Guard ; votre camp ; les codes de votre copie ; des vérifications des fichiers du jeu que votre copie a changés, et des vérifications régulières que le jeu de chaque joueur reste le même ; vos mods avec leurs vérifications ; les commandes de script que vos mods lient à des touches (jamais ce que vous appuyez) ; pour la copie de test d'un développeur, la clé du développeur ; les noms des éventuels outils de triche listés trouvés en cours d'exécution ; le début et la fin de la partie ; et le replay le plus récent enregistré sur votre PC pendant ou juste après la partie, avec son nom de fichier. Un replay contient chaque ordre donné par chaque joueur dans la partie, et son nom de fichier et son contenu peuvent inclure les noms en jeu de vous-même et d'autres joueurs.
- Ce qu'il ne fait jamais : il ne collecte jamais votre écran ni vos frappes au clavier, ne regarde jamais à l'intérieur d'autres programmes pendant qu'ils tournent, et ne nous envoie jamais vos fichiers, hormis le replay qu'un enregistrement de partie porterait. Des rapports de plantage du jeu, il ne lit que sa propre ligne sur une copie de triche qu'il a arrêtée (ci-dessus), sur votre PC.
- Les copies de test de développeurs : les applications sont conçues pour laisser entrer dans une partie la copie de test d'un développeur munie d'une clé spéciale de notre part, la seule exception à la règle des copies de triche. Aucune ne fonctionne encore : les applications ne peuvent pas vérifier une telle clé aujourd'hui.
- Les décisions vous concernant : pas de bannissement automatique.   - combien de mods à vous vous aviez, et quels genres de choses ils contiennent, comme des unités, des cartes, des missions ou des scripts (comptés par genre, jamais nommés, et jamais leurs mots, chemins ou fichiers) ;
- tout de suite, quand une application plante : le type d'erreur et l'endroit dans notre code ;
- tout de suite, après le plantage d'un jeu que l'application a lancé, des détails techniques sur l'endroit et la manière dont il a planté :
  - le code d'erreur du jeu ; le nom du fichier dans lequel il s'est arrêté (ce peut être une partie de Windows, un pilote, ou un autre programme chargé dans le jeu, comme une surcouche), l'endroit de ce fichier où le jeu s'est arrêté, et jusqu'à 16 endroits du jeu qui y ont mené ;
  - pour une erreur de mémoire, ce que le jeu essayait de faire (lire, écrire ou exécuter) et l'endroit en mémoire ;
  - pour une erreur de script, le texte d'erreur du jeu lui-même, avec les chemins sur un disque raccourcis en noms de fichiers, le nom de votre dossier utilisateur masqué (les noms des dossiers qu'il contient peuvent rester), et les numéros de compte Steam et autres longs nombres retirés (les noms de scripts du jeu lui-même restent) ; combien d'erreurs précédentes le jeu avait ignorées ; et la carte (une carte du jeu par son nom, la carte d'un mod seulement comme « une carte de mod ») ;
  - l'unité que le jeu était en train de créer, quand les applications peuvent la lire dans le rapport de plantage du jeu (une unité du jeu par son numéro, l'unité d'un mod seulement comme « une unité de mod ») ;
  - quels mods étaient activés, quels genres de choses vos propres mods contiennent (comptés par genre), et quelle version de ces conditions vous avez acceptée.

Bug Watch n'utilise que les rapports de plantage du jeu lui-même. D'un rapport d'un autre programme, il ne lit que les noms des fichiers qu'il liste, pour constater que ce n'est pas celui du jeu ; rien n'en est envoyé.

Chaque envoi porte votre nom d'utilisateur et votre identifiant d'installation, un code aléatoire créé sur votre PC quand vous avez choisi votre nom d'utilisateur pour la première fois, que vous cochiez Bug Watch ou non. Votre code de rapport, que les Réglages affichent tant que Bug Watch est activé, est constitué des 8 premiers caractères de votre identifiant d'installation.

Nos applications n'envoient jamais vos fichiers ni les fichiers de rapport de plantage du jeu eux-mêmes, et Bug Watch n'envoie aucun numéro de compte Steam. (Le rapporteur de plantage du jeu lui-même peut envoyer son propre rapport au créateur du jeu : section 3.) Le texte d'erreur du jeu peut contenir des noms issus du jeu ou des scripts d'un mod. Merci de ne pas utiliser votre vrai nom comme nom d'utilisateur (section 9).

Plantages connus : avec Bug Watch activé, si le jeu plante d'une des façons que nous connaissons, le Launcher vous dit quelle unité le jeu était en train de créer et pourquoi, dans votre langue. Cette explication ne vous est montrée qu'à vous, jamais envoyée ; le rapport de Bug Watch ne porte l'unité que comme indiqué plus haut (un numéro, ou « une unité de mod »). Pour connaître ces plantages, les applications téléchargent notre liste depuis notre serveur Bug Watch au lancement d'un jeu, sauf si la liste sur votre PC a moins d'un jour, et une fois de plus lors d'un plantage s'il n'y a pas de liste utilisable. Décocher Bug Watch supprime la liste de votre PC.

Avec Bug Watch activé ou désactivé : si un jeu lancé par le Launcher plante, le Launcher vous montre un court code de plantage, calculé sur votre PC à partir de l'endroit où le jeu s'est arrêté. Vos mods, cartes, exports et sauvegardes dans le dossier RUSE 2.0 de Documents, votre copie moddée et la sauvegarde propre de votre jeu restent aussi jusqu'à ce que vous les supprimiez.

## 12. Mises à jour, et autres sites auxquels les applications se connectent

- Mises à jour : une fois ces conditions acceptées, les deux applications demandent à GitHub à chaque démarrage s'il existe une nouvelle version ; tant que vous n'avez pas accepté, elles ne demandent rien. Si une mise à jour est disponible et que votre langue n'est pas l'anglais, les applications récupèrent aussi ses notes sur GitHub. Les mises à jour facultatives s'installent quand vous appuyez sur Mettre à jour. Une mise à jour que nous marquons comme obligatoire se télécharge et s'installe toute seule au démarrage de l'application, sans demander, et Jouer et Tester en jeu attendent qu'elle soit installée. Dans les deux cas, une mise à jour ne s'installe que si elle porte notre signature et est exactement le fichier que nous avons signé ; sinon rien ne s'installe, et l'application le dit et vous renvoie vers notre Discord. Si son téléchargement échoue trois fois, l'application cesse d'essayer toute seule et vous renvoie vers sa page de version sur GitHub ; une mise à jour obligatoire continue de faire attendre Jouer et Tester en jeu. Notre clé de signature n'est jamais envoyée en ligne. Au démarrage suivant après une mise à jour, l'application supprime le programme d'installation de cette mise à jour. Si vous avez déjà téléchargé des unités d'époque, le Studio vérifie aussi au démarrage s'il en existe de nouvelles versions et les télécharge tout seul. Seule la version la plus récente de chaque application reçoit des correctifs.
- En dehors de nos propres serveurs, les applications se connectent à ces sites. Chacun voit votre adresse IP et ce qui est demandé, et peut garder des journaux selon sa propre politique de confidentialité :
  - GitHub (Microsoft) : les mises à jour et leurs notes ; la liste des mods et les mods qui y figurent (au premier démarrage, le Launcher récupère la liste juste après l'écran des conditions) ; les unités d'époque ; les correctifs du jeu, pendant une construction qui en a besoin ; et certains fichiers de mouvements ;
  - tout autre site que notre liste de mods peut nommer pour un mod : le téléchargement de ce mod (le Launcher vérifie d'abord la taille et la somme de contrôle de chaque fichier par rapport à la liste) ;
  - Poly Haven et ambientCG : les textures en ligne gratuites de Map Paint, dont les petites images sont chargées depuis les adresses que ces sites donnent (ambientCG reçoit les mots que vous tapez dans sa recherche) ;
  - la National Map de l'U.S. Geological Survey : des photos aériennes (il reçoit la zone autour de l'endroit que vous choisissez) ;
  - Zenodo, et une collection publique de fichiers de mouvements sur GitHub : les mouvements dans RUSE Decoy, l'onglet son et animation du Studio ;
  - notre serveur Bug Watch : la liste des plantages connus du jeu, seulement tant que Bug Watch est activé (section 7) ;
  - Steam : la page de connexion, et les propres liens de Steam qui lancent Steam ou vérifient les fichiers du jeu ;
  - Microsoft : Edge WebView2 dessine les fenêtres des applications, et ce qu'il envoie à Microsoft est réglé par Windows et Microsoft, pas par nous. Si Windows n'a pas un certificat de sécurité dont les applications ont besoin pour joindre GitHub, les applications demandent à Windows de le vérifier, et Windows peut alors le télécharger depuis Microsoft ou depuis son émetteur. Là où WebView2 manque, les installateurs (une case cochée que vous pouvez décocher), les applications au démarrage (« L'installer maintenant ? ») et les Réglages (« Installer WebView2 ») proposent l'installateur WebView2 de Microsoft, fourni avec les applications ; si vous dites oui, il télécharge WebView2 depuis Microsoft et l'installe, selon les conditions de Microsoft. Si vous dites non, vous utilisez l'application dans votre navigateur à la place.
- Les vues 3D du Studio se dessinent avec une bibliothèque fournie dans le Studio, donc rien n'est téléchargé pour elles.
- Les boutons qui ouvrent votre navigateur : nos pages GitHub et Discord, la page d'accueil d'un mod, le téléchargement de WebView2 chez Microsoft, blender.org, et les pages de crédits des unités d'époque. « Signaler un problème », « Add my mod » et « Ouvrir un ticket sur GitHub » ouvrent une page GitHub avec des détails déjà remplis : l'erreur que l'application a montrée (avec votre nom d'utilisateur Windows retiré de tous les chemins), les détails de votre mod, ou votre code de dossier. Votre navigateur envoie ces détails à GitHub dans l'adresse de la page dès que la page s'ouvre ; rien n'est publié tant que vous ne le publiez pas, et ce que vous publiez sur GitHub est public.
- Si les applications ne peuvent pas ouvrir leur propre fenêtre (par exemple sous Linux via Proton), elles s'ouvrent à la place dans votre navigateur web, et votre navigateur charge alors lui-même les petites images des textures.
