# 出问题时

找到你看到的情况，然后按照解决办法操作。

## 先试试故障排查

**故障排查** 会一次性检查可能阻止测试或 **开始游戏** 的情况：是否找到了游戏、Steam 是否在运行、
是否有从模组版副本启动后仍在运行的 R.U.S.E.、驱动器及其剩余空间、残留的副本、只读文件，
以及应用能否在副本存放的位置写入。它能修复的每个问题都有一个按钮；其余的会说明该怎么做。

- 在 RUSE Studio 中：在 **在游戏中测试** 旁边，以及 **设置 > 帮助** 中。
  在 RUSE Launcher 中：底部栏，以及每条问题消息上（Studio 0.8.0、Launcher 0.3.0）。
- **复制报告** 会生成一段文字，可以粘贴到 [[错误报告|报告错误]] 里（不包含你的 Windows 用户名）。

## 游戏本身好像被改动了（被其他模组管理器或手动修改）

**设置 > 游戏的干净备份** 会保留一份游戏文件的干净副本，用它来检查游戏文件，并把改动过的恢复原样。
不属于游戏的文件会被移到一边，绝不会被删除。或者用 **通过 Steam 验证** 让 Steam 修复游戏。
这是应用唯一会写入你游戏文件夹的地方，而且只在你要求时才会。

## Studio 标题栏下方出现红条

那是 **模组检查**。当你选择模组时，以及在 **在游戏中测试** 之前，Studio 会像游戏构建那样读取你模组的每个文件。
每个问题都用通俗的话说明（哪里不对、在哪张地图上、该怎么做），能修复的地方会带一个修复按钮：
填上缺少的数值、拿掉出错的那一项或那一个设置，或者把文件搁置。原来的文件会保留在它旁边。
**详细信息** 会显示构建自己的原话，求助时很有用。

- **搁置**（在损坏的地图文件旁边）会把它重命名为原文件旁边的 `<name>.broken.toml`：什么都不会丢失，
  模组没有它也能运行，那张地图会从干净的状态开始。
- `mod.toml` 或单位修改中的问题没有“搁置”：打开文件，修正红条指出的那一行，或者到
  [Discussions > Help](https://github.com/sneadtristen6/R.U.S.E-2.0-Project/discussions) 提问。

> [!NOTE]
> 已知情况：RUSE Studio 0.7.0 及更早版本保存的 **水面** 笔触没有水位（“the water brush
> needs level”）。0.7.1 修复了这个问题；**搁置** 可以清掉旧文件。

## 应用打开得很慢

- **安装后第一次启动** 时，如果勾选了“保留一份我的游戏文件的干净副本”，就会制作这份副本
  （整个游戏文件夹，大约 5.3 GB）：设置 会显示进度，这期间应用照常可以使用。
- **RUSE Studio 的游戏索引** 每个游戏版本建立一次，Studio 更新改变了它时会再建立一次
  （大约一分钟；Studio 会先问你）。这期间 地图 标签页和 设置 都可以使用，
  底部那一行会在它就绪时告诉你。
- 其他情况：打开 **故障排查**，然后点 **复制报告**。报告会列出应用最近几次启动时每一步各花了多少秒：
  把它粘贴到 [[错误报告|报告错误]] 里。同样的内容也保存在
  `%LOCALAPPDATA%\RUSE Mod Platform\logs\studio-start.log` 中（Launcher 的是：`launcher-start.log`）。

## “Windows 已保护你的电脑”

这些应用对 Windows 的信誉检查来说还是新面孔。点击 **更多信息**，然后点 **仍要运行**。

## “certificate verify failed: unable to get local issuer certificate”（或“unable to get issuer certificate”）

任何模组都下载不了，或者更新下载不了。Windows 还没有获取用来校验 GitHub 的证书；
从 Launcher 0.4.8.4 和 Studio 0.9.8.4 起，应用会向 Windows 请求这个证书，然后重试。从 Launcher 0.4.8.9 和 Studio
0.9.8.9 起，它们还会用自带的 Firefox 所用的证书列表再试一次，以应对 Windows 无法获取证书的电脑
（证书更新被关闭或被阻止：“unable to get issuer certificate”，或“此电脑不信任该网站的安全证书”）。
如果是较旧的应用，更新也无法下载：请在浏览器中从
[发布页](https://github.com/sneadtristen6/R.U.S.E-2.0-Project/releases) 获取安装程序并运行它（它会覆盖安装旧版本，
和更新一样）。模组总是可以在浏览器中从模组列表的
[发布页](https://github.com/sneadtristen6/Ruse-Mods/releases) 下载，然后在 Launcher 中用 **添加模组文件…** 添加。
如果新版应用仍然这样提示：扫描安全（HTTPS）连接的杀毒软件、学校或公司的网络，或者电脑上的日期不对，都可能导致这个问题；
请在 [Discussions > Help](https://github.com/sneadtristen6/R.U.S.E-2.0-Project/discussions) 告诉我们。

## 测试或游玩时出现“[WinError 5] Access is denied”

Windows 拒绝删除应用制作的一份游戏副本（在 `RUSE-Instances` 中）。还有：“无法删除位于
`...\RUSE-Instances\<name>.old` 的旧模组版副本”，每隔一次 **在游戏中测试** 或 **开始游戏** 就出现一次。

- **先更新**（应用打开时会提供更新）：从 RUSE Studio 0.7.6 和 Launcher 0.2.11 起，
  Windows 不肯删除的副本永远不会阻止测试：它会被移到 `RUSE-Instances\.trash` 中，等没有东西占用它时在那里删除。
- **R.U.S.E. 还在从之前的测试中运行？** 应用会这样提示，并给出程序的名称：关闭游戏
  （在任务管理器的 详细信息 标签页中查找 `RUSE.exe`），然后再试一次。**故障排查** 会找到仍在从副本运行的游戏和残留的副本，
  并替你删除它们。
- **使用较旧的版本：** 删除消息中指出的文件夹（`...\RUSE-Instances\<name>.partial` 或 `.old`；
  Windows 会询问只读文件：选“是”；删除的只是副本，绝不会是游戏本身），然后再试一次。如果 Windows
  拒绝，请先重启 Windows。
- 还是不行？带上完整的消息 [[报告它|报告错误]]。

## 应用找不到 R.U.S.E.

**设置 > 游戏文件夹 > 选择文件夹…**，然后选择包含 `RUSE.exe` 的文件夹（在 Steam 中：
`steamapps\common\R.U.S.E`）。

## “无法确认这份 R.U.S.E. 副本”

R.U.S.E. 2.0 只能配合你拥有的游戏副本使用。在游戏文件夹得到确认之前，**开始游戏** 和 **在游戏中测试**
保持不可用，这个框会说明原因：Steam 没有 R.U.S.E. 安装在那个文件夹里的记录；里面 Steam 自己的文件
（`steam_api64.dll`）缺失、被改动，或者不是 Valve 的；或者文件夹里有让游戏不经
Steam 就能运行的文件（框里会列出它们的名称）。

- **你在 Steam 上拥有它：** 点击 **在 Steam 中检查我的文件**（Steam 会把它缺失或被改动的文件放回去），
  删除框里列出的所有文件，然后点击 **重新检查**。你手动选择的游戏文件夹必须是
  Steam 安装的那个。
- **你通过别的方式拥有它**（R.U.S.E. 上架 Steam 之前的盒装版），**或者你认为检查
  出错了：** 框里会显示 **你的代码**（根据这台电脑和游戏文件夹生成）。点击 **复制**，然后点 **在 Discord 提交工单**
  或 **在 GitHub 提交工单** 并把它粘贴进去。我们会发给你一个解锁码：把它粘贴到 **解锁码** 下，
  然后点击 **解锁**。它会在那台电脑上确认那份副本。

在 Windows、Linux 和 Steam Deck 上，检查都是一样的。这个项目绝不帮助任何人在没有拥有 R.U.S.E. 的情况下玩它：
不分发游戏文件，也不让它不经 Steam 运行。

## “使用较旧的模组格式”或“由较新的 RUSE Studio 保存”

- **较旧的模组格式：** 这个模组是用较旧的 Studio 制作的。**更新此模组** 会按这个 Studio 读取的方式重写它的文件，
  保持它们的含义不变；会先把整个模组打包成一个 zip，放进 Studio 的 `Backups` 文件夹。
- **较新的 RUSE Studio：** 修改那个模组之前请先更新 Studio：较旧的版本可能会丢失它不认识的内容。

## 关闭 Studio 时问“关闭 RUSE Studio？”

还有东西没有保存，框里会说明是什么（一个输入了文字但还没确认的框、一个正在保存的改动、
在游戏中测试 仍在构建……）。**否** 保持 Studio 打开；**是** 关闭它，那些内容会丢失。

## 游戏启动了，但没有我的修改

1. 它是从 **开始游戏**（Launcher）或 **在游戏中测试**（Studio）启动的吗？从 Steam 启动时，游戏不带模组。
2. 地图的修改只在那张地图上显示：在主菜单中点击 **战斗** 并选择它
   （Studio 在 在游戏中测试 之后显示的消息会说明是哪个按钮和哪张地图）。
3. 模组在组合中吗？顺序在它下面的某个模组是否修改了同样的东西？

## 游戏崩溃

记下你在崩溃前刚做了什么（哪张地图、什么命令、屏幕上有什么），截一张图，然后
[[报告它|报告错误]]。正是靠编辑过的地图上的崩溃报告，地图工具才变得可靠。
