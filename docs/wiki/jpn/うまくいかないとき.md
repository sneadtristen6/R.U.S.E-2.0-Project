# うまくいかないとき

表示されているものを探して、その直し方に従ってください。

## まずトラブルシューティングを試す

**トラブルシュート**（Launcher では **トラブルシューティング**）は、テストや **プレイ** を止めうるものを一度に確認します: ゲームが見つかるか、Steam が動いているか、MOD入りのコピーから起動した R.U.S.E. が動いたままになっていないか、ドライブとその空き容量、残ったコピー、読み取り専用のファイル、そしてコピーの保存先にアプリが書き込めるか。直せる問題にはボタンがあり、それ以外は何をすればよいかを表示します。

- RUSE Studio では: **ゲームでテスト** の隣と、**設定 > ヘルプ** に。RUSE Launcher では: 下部のバーと、すべての問題のメッセージに（Studio 0.8.0、Launcher 0.3.0）。
- **レポートをコピー** で、[[バグの報告|バグの報告]] に貼り付けるテキストが得られます（Windows のユーザー名は含まれません）。

## ゲーム本体が変わってしまったようだ（他のMODマネージャーや手作業の編集で）

**設定 > ゲームのクリーンなバックアップ** は、ゲームのファイルのクリーンなコピーを保存し、ゲームのファイルをそれと照らし合わせて、変わったものを元に戻します。ゲームのものでないファイルは脇に移され、削除されることはありません。または **Steam で検証** で、Steam にゲームを修復させます。アプリがゲームフォルダーに書き込むのはここだけで、それも頼んだときだけです。

## Studio のヘッダーの下に赤いバーが出る

それは **MODチェック** です。MODを選んだとき、そして **ゲームでテスト** の前にもう一度、Studio はゲームのビルドと同じやり方でMODのすべてのファイルを読みます。それぞれの問題は分かりやすい言葉で示され（何が悪いか、どのマップか、何をすればよいか）、直せるものには直すボタンが付きます: 足りない値を埋める、間違っている1つの項目や設定を取り除く、またはファイルを脇に置く。元のファイルはその隣に残ります。**詳細** はビルド自身の言葉を表示します。助けを求めるときに便利です。

- **脇に置く**（壊れたマップファイルの隣）は、それを元のファイルの隣で `<name>.broken.toml` に名前を変えます: 何も失われず、MODはそれなしで動き、そのマップはまっさらな状態から始まります。
- `mod.toml` やユニットの編集の問題には「脇に置く」がありません: ファイルを開いてバーが示す行を直すか、[Discussions > Help](https://github.com/sneadtristen6/R.U.S.E-2.0-Project/discussions) で質問してください。

> [!NOTE]
> 既知のケース: RUSE Studio 0.7.0 以前は、**水** のストロークを水面の高さなしで保存していました（「the water brush needs level」）。0.7.1 で直っています。古いファイルは **脇に置く** で片付きます。

## アプリが開くまでに時間がかかる

- 「ゲームファイルのクリーンなコピーを保存する」にチェックを入れていると、**インストール後の初回起動** でそのコピーを作ります（ゲームフォルダー全体で、約 5.3 GB）: 進み具合は設定に表示され、その間もアプリは使えます。
- **RUSE Studio のゲーム索引** は、ゲームのバージョンごとに1回作られ、Studio の更新で変わったときにもう一度作られます（1分ほど。Studio は先に尋ねます）。その間もマップタブと設定は使え、準備ができると下部の行が知らせます。
- それ以外: **トラブルシュート** を開き、**レポートをコピー**。レポートには、アプリの最近の起動それぞれで各段階にかかった時間が秒で並びます: [[バグの報告|バグの報告]] に貼り付けてください。同じ行は `%LOCALAPPDATA%\RUSE Mod Platform\logs\studio-start.log` にも残ります（Launcher のものは `launcher-start.log`）。

## 「WindowsによってPCが保護されました」

アプリは Windows の評価チェックにとってまだ新しいものです。**詳細情報** をクリックし、次に **実行** をクリックしてください。

## 「certificate verify failed: unable to get local issuer certificate」（または「unable to get issuer certificate」）

MODがダウンロードされない、または更新がダウンロードされない。Windows が、GitHub の確認に使う証明書をまだ取得していませんでした。Launcher 0.4.8.4 と Studio 0.9.8.4 からは、アプリが Windows に証明書を求めて、もう一度試します。Launcher 0.4.8.9 と Studio 0.9.8.9 からは、Windows が証明書を取得できない PC（証明書の更新がオフ、またはブロックされている: 「unable to get issuer certificate」、または「この PC はサイトのセキュリティ証明書を信頼していません」）のために、アプリが同梱している Firefox の証明書リストでも試します。古いアプリでは更新もダウンロードできません: ブラウザーで [リリース](https://github.com/sneadtristen6/R.U.S.E-2.0-Project/releases) からインストーラーを入手して実行してください（更新と同じく、古いものの上にインストールされます）。MODはいつでも、ブラウザーでMODリストの [リリース](https://github.com/sneadtristen6/Ruse-Mods/releases) からダウンロードし、Launcher の **MODファイルを追加…** で追加できます。新しいアプリでもまだ表示される場合: 安全な（HTTPS）接続をスキャンするウイルス対策ソフト、学校や職場のネットワーク、PC の日付の誤りが原因になることがあります。[Discussions > Help](https://github.com/sneadtristen6/R.U.S.E-2.0-Project/discussions) で教えてください。

## テストやプレイのときに「[WinError 5] Access is denied」

アプリが作ったゲームのコピー（`RUSE-Instances` の中）を、Windows が削除させませんでした。**ゲームでテスト** や **プレイ** の2回に1回、「An old modded copy at `...\RUSE-Instances\<name>.old` can't be removed」と出ることもあります。

- **まず更新する**（アプリは開くときに勧めます）: RUSE Studio 0.7.6 と Launcher 0.2.11 からは、Windows が削除しないコピーがテストを止めることはありません: そのコピーは `RUSE-Instances\.trash` に移され、何も使わなくなったらそこで削除されます。
- **前のテストの R.U.S.E. がまだ動いていませんか？** アプリがプログラムの名前と一緒にそう知らせます: ゲームを閉じて（タスクマネージャーの「詳細」タブで `RUSE.exe` を確認してください）、もう一度試してください。**トラブルシュート** は、コピーから動いたままのゲームと残ったコピーを見つけ、削除してくれます。
- **古いバージョンでは:** メッセージが示すフォルダー（`...\RUSE-Instances\<name>.partial` または `.old`）を削除してから（Windows が読み取り専用ファイルについて尋ねたら「はい」と答えてください。消えるのはコピーだけで、ゲームは消えません）、もう一度試してください。Windows が拒否する場合は、先に Windows を再起動してください。
- それでも出る場合は、メッセージ全体を添えて [[報告してください|バグの報告]]。

## アプリが R.U.S.E. を見つけられない

**設定 > ゲームフォルダ > フォルダを選ぶ...** で、`RUSE.exe` があるフォルダーを選びます（Steam なら: `steamapps\common\R.U.S.E`）。

## 「この R.U.S.E. のコピーを確認できませんでした」

R.U.S.E. 2.0 は、あなたが所有しているゲームのコピーでしか動きません。ゲームフォルダーが確認されるまで **プレイ** と **ゲームでテスト** はオフのままで、このボックスにその理由が表示されます: そのフォルダーに R.U.S.E. がインストールされた記録が Steam にない。そのフォルダーにある Steam 自身のファイル（`steam_api64.dll`）がない、変更されている、または Valve のものではない。あるいは、フォルダーにゲームを Steam なしで動かすファイルがある（ボックスがその名前を示します）。

- **Steam で所有している場合:** **Steam でファイルを確認** をクリックし（Steam が、なくなったり変更されたりした自分のファイルを元に戻します）、ボックスに名前が出たファイルを取り除いてから、**もう一度確認** をクリックします。手作業で選んだゲームフォルダーは、Steam がインストールしたフォルダーでなければなりません。
- **ほかの方法で所有している場合**（R.U.S.E. が Steam に来る前のパッケージ版）、**またはチェックが間違っていると思う場合:** ボックスに **あなたのコード**（この PC とゲームフォルダーから作られたもの）が表示されます。**コピー** をクリックしてから、**Discord でチケットを作成** か **GitHub でチケットを作成** をクリックして、それを貼り付けてください。こちらからロック解除コードをお送りします: それを **ロック解除コード** の下に貼り付けて、**ロック解除** をクリックしてください。これで、その PC でそのコピーが確認されます。

チェックは Windows、Linux、Steam Deck で同じです。このプロジェクトは、R.U.S.E. を所有せずに遊ぶ手助けを決してしません: ゲームのファイルを配ることも、Steam なしで動かすこともありません。

## 「古い Mod 形式です」または「新しい RUSE Studio で保存されています」

- **古いMOD形式:** そのMODは古い Studio で作られました。**この Mod を更新** で、意味を保ったまま、この Studio が読む形にファイルを書き直します。その前に、MOD全体の zip が Studio の `mod-backups` フォルダーに入ります。
- **新しい RUSE Studio:** そのMODを変更する前に Studio を更新してください: 古い Studio は、知らない内容を失うおそれがあります。

## Studio を閉じようとすると「RUSE Studio を閉じますか？」と聞かれる

まだ保存されていないものがあり、ボックスにそれが何かが表示されます（文字を入力したまま確定していないボックス、保存中の変更、ビルド中の ゲームでテスト など）。**いいえ** で Studio を開いたままにし、**はい** で閉じて、それを失います。

## ゲームは始まるが、自分の変更が入っていない

1. **プレイ**（Launcher）か **ゲームでテスト**（Studio）から起動しましたか？ Steam から起動すると、ゲームはMODなしで始まります。
2. マップの変更はそのマップでだけ表示されます: メインメニューで **バトル** をクリックし、そのマップを選んでください（「ゲームでテスト」の後の Studio のメッセージに、どのボタンとマップかが書かれています）。
3. そのMODはセットに入っていますか？ 順番が下のMODが、同じものを変えていませんか？

## ゲームがクラッシュする

直前に何をしたか（どのマップ、どの命令、画面に何があったか）を書き留め、スクリーンショットを撮って、[[報告してください|バグの報告]]。編集したマップでのクラッシュの報告のおかげで、マップのツールはしっかりしたものになりました。
